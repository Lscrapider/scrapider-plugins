# 桌面复演用例

这些事实取自共同题面。逐条跟着计划行动，用可找到的步骤、文件、条件和验收证据评估。现场联调仍属于计划预期。

| 编号 | 入口和输入 | 应能在计划里追到 |
| --- | --- | --- |
| E1 | A、A2、B 同权限且 A2 与 A 同租户。A 发带 B 租户参数的列表/详情/名称检查，B 已有同名批次。 | 真身份，写入 owner，分页与计数之前过滤，A/B 可以分别拥有同名数据，同租户重复失败，B 详情按不存在的语义。 |
| E2 | A 提交 A 的批次 ID 混 B 的文件，或 A 具备上传操作权限并取得 B 的 fileId/uploadId。 | 现有 controller/service 与指定修改拥有者，父关系和租户拒绝点在 MinIO、数据库、签发链接之前，旧物理引用仍受保护。 |
| E3 | A 的合法流水线一组输入里有 A 和 B 批次。另用同租户输入触发正常运行。 | 外租户输入整体拒绝且无关系/消息，正常的运行和原有状态约束可复现。 |
| E4 | 合法消息入口收到 A 的任务 ID 与 B 的执行 ID 组合。另重复投递已处理的合法回调。 | 匹配路线、租户从可信记录取、现有版本/幂等保护，拒绝/重复前后状态以及消息和产物取证。 |
| E5 | 表结构已经扩展，旧写者仍可写入未归属记录，并且有历史创建人的租户曾改变。 | 兼容结构和已启用隔离的区别，能继续做的工作，迁移歧义和停写排空证据，切换失败怎样保持范围。 |
| E6 | 协调者只看总计划，执行者只看分片处理或任务绑定所分配的工作和直接链接。 | 可开始 vs 可交付、共同产出、跨模块依赖、持久化/异步副作用所在文件、需要补问的信息。 |

如果计划提出了不同的具体技术形状，在相同业务预期下以它自己承诺的入口做静态复演。审查者记录阻塞条件、重大错法及其后果，也记录哪些证据已经被定位到可执行的命令、输入和观察结果。若计划只有待证实的非生产联调，将其记在验收证据，不把可实施步骤一概视为阻塞。
