# 租户读写隔离执行计划对照协议

## 试验单位

三个独立写作者对同一真实工作树题面生成计划。组别为 Scrapider 第二档、Scrapider 第三档、Superpowers 7.0.0 writing-plans。写作者统一 gpt-6-luna/max、独立上下文、只读相同业务仓库、相同需求和证据、相同工具权限和变更限制。输出只放各自实验目录，禁止把别路计划、已有计划或本协议的结论当输入。Superpowers 组读指定本地版本的写作说明并按用户和项目规则调整越权步骤。对照的是写作输出，执行能力在桌面复演中验证。

输入以 requirements.md、source-evidence.md、源文件指纹和 armJ2 中适用的 AGENTS.md 固定。业务仓库没有 Git HEAD，使用指定源码集合的稳定内容指纹。运行 Maven 只在临时复制里执行已有用例，作为基线回归证据。

## 复演与记录

评审者读取实际原稿，可看见布局和组别。各项按可执行、部分覆盖或存在缺口记录证据，并引用文件与行号。

| 项目 | 需从计划恢复的信息 |
| --- | --- |
| 身份与覆盖 | 可信租户来源，功能权限和数据权限共同生效，列表、详情、聚合、关联和外部副作用均走实际入口 |
| 归属与迁移 | 存量归属可证、孤儿与跨租户关系如何处理，新旧写入方和切换条件 |
| 分工与开工 | 真实输入、修改拥有者、只读依赖，哪几份工作能依据已定契约准备 |
| 可用交接 | 哪些改动一起落地才可用，预置条件有解，旧版本、临时构建和最终启用的证据分得清 |
| 跨边界完整性 | 多条调用链涉及同一资源时能否把保护放到正确的业务、数据或异步边界 |
| 验收证明 | A/B 同权限对照的可观察结果、状态/消息/存储副作用、历史与异常、验证命令和未实测缺口 |
| 执行可读性 | 仅从任务及其直接链接能否确定改哪里、依赖什么、先做什么、如何证明、何时可交付 |
| 导航与可维护性 | 统计原始文件/字节，核对相对链接、权威定义和证据索引是否重复或漂移 |

冷读用例选在两处。执行者拿到上传/文件副作用入口，以及任务绑定/异步执行入口后，各自回填写集、开始条件、预期结果、拒绝位置和验证证据。协调者从总计划推演 schema → 可读旧数据 → 跨模块集成 → 运行启用，以及已有后台回调跨租户或重复投递时的预期。

计划中列出的测试命令与已经跑过的检查分别记录。涉及真实租户权限、消息和存储副作用的 E2E 是未来实施验收。本次评价不把静态复演或既有未修改用例转成隔离已上线的结论。
